# The open-coder-ai visual language

Every figure in every open-coder-ai repository is generated by a script, ships as a light and a dark
SVG, and is regenerated in CI so a stale figure fails the build. This file is the standard those
scripts implement. The implementation is `docs/figures/palette.py`, carried byte-identically in
`agentseam`, `chock`, `chock-catalog` and `context-report`; if this file and that one disagree, the
code is right and this file is wrong.

## The one rule everything else follows

**A figure may not claim more than the data behind it.** These projects exist to say precisely what
enforces and what only advises, so a chart that implies otherwise does more damage than no chart.
That single rule generates most of what follows: why absence has its own colour, why every colour
also carries a label, and why nothing is drawn from a number somebody typed.

## Colour

One hue, walked in steps. Nothing is decorative; every colour is a claim about strength.

**`ENFORCEMENT` — the ordinal 3-step scale.** `advisory < in-agent < enforced`, weakest first.
Never reorder it.

| step | light | dark |
|---|---|---|
| advisory | `#86b6ef` | `#9ec5f4` |
| in-agent | `#2a78d6` | `#3987e5` |
| enforced | `#104281` | `#184f95` |

**`LEVELS` — the ordinal 5-step scale**, for data graded more finely (agentseam's capability
matrix). The same hue walked further: light `#86b6ef #5598e7 #2a78d6 #1c5cab #104281`,
dark `#9ec5f4 #6da7ec #3987e5 #256abf #184f95`.

**`NEUTRAL` — absence.** Light `#d8d7d2`, dark `#383835`. This is the load-bearing one. A cell
meaning *not supported*, *no evidence*, *does not apply* is neutral — **never** the pale end of a
ramp. Pale blue reads as "a little bit supported", which is a false claim about a thing that does
not exist. Absence is a different kind, not a low score.

**Ground and type.** `SURFACE` light `#fcfcfb` / dark `#1a1a19`; `TEXT` light `#0b0b0b` /
dark `#ffffff`; `TEXT_SECONDARY` light `#52514e` / dark `#c3c2b7`.

## Accessibility

- **Colour is never the only carrier of meaning.** Every cell, bar and segment also carries a text
  label, a glyph, or a position saying the same thing. Render to PNG, convert to greyscale, and read
  it. If it stops being readable, the figure is not finished.
- Every figure is `role="img"` with `aria-labelledby`, a `<title>` and a `<desc>`. The `<desc>` is
  real alt text stating the figure's **conclusion** — "no agent reaches the enforced tier at
  pre_tool", not "a matrix of agents and events".
- Identifiers (repository names, event names, policy ids) are set in `MONO`, prose in `SANS`. A
  reader should be able to tell a thing they can type from a thing they can only read.

## Form

- Geometry: `STROKE_WIDTH = 2`, `CORNER = 4`, `GAP = 2` (surface showing between adjacent fills),
  `GRID_OPACITY = 0.3`.
- **No images of code. No pie charts. No dual-axis charts. No new badges. No animation** beyond the
  demo GIFs that already exist.
- Figures are embedded at `width="760"`; the family diagram is 800 wide and embedded at `width="800"`.
  Check legibility at that width before shipping — not at full size.

## Generation

Generators are **stdlib-only** plus `palette`. Rendering to PNG for inspection may use `cairosvg`,
but nothing in CI may depend on it.

`palette.write_pair(stem, render)` writes `<stem>-light.svg` and `<stem>-dark.svg` from one
`render(theme_colours, theme_name)` function, so the two themes can never drift apart. Helpers:
`theme`, `open_svg`, `close_svg`, `box`, `text`, `arrow`, `wrap`, `esc`.

**Every number in a figure is read from the repository at generation time** — the matrix module, the
policy files, a real `produce` run. None is typed into the generator. This is what makes a figure
evidence rather than decoration, and it is why the CI job below exists.

## Embedding

```html
<picture>
  <source media="(prefers-color-scheme: dark)" srcset="https://raw.githubusercontent.com/open-coder-ai/REPO/main/docs/figures/STEM-dark.svg">
  <img alt="STATES THE CONCLUSION" src="https://raw.githubusercontent.com/open-coder-ai/REPO/main/docs/figures/STEM-light.svg" width="760">
</picture>
```

Absolute raw URLs, because these READMEs also render on PyPI where relative paths break.

## CI

One job per repository, added to the existing CI workflow, with every action pinned to the SHA that
repository already uses:

```yaml
  figures:
    steps:
      - name: Regenerate figures
        run: cd docs/figures && for g in make_*.py; do python "$g"; done
      - name: Fail on drift
        run: git diff --exit-code -- docs/figures
```

A committed figure that no longer matches what its generator produces is a build failure, exactly
like a stale golden. That is the whole point: the figures cannot quietly drift out of agreement with
the code they describe.

## The family diagram

`docs/figures/make_family.py` and its two SVGs are **shared, byte-identical, and not per-repo
work**. Four repositories showing four subtly different pictures of the same family would be worse
than showing none. Change it in one place and copy it out; verify with `sha256sum`.

## Social cards

`docs/figures/social-card.svg` at 1280x640, light only — GitHub's social preview has no dark
variant — rendered to a committed `.png`, which is what gets uploaded. It carries the repository
name in `MONO`, one line of what it is, and one true number drawn from the same real data as that
repository's figure. Nothing else.
